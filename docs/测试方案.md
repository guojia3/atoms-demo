## 1. 测试目标

1. 验证产品是否满足最小闭环：输入一句话 → 智能体生成 → 沙箱可视化运行 → 数据持久化。
2. 逐条验证验收项 A1-A12、交付要求 H1-H7、评分关注点，以及 R1-R13 中可在运行时验证的要求。
3. 对单元、接口、WebUI、安全、并发、异常、兼容性、持久化八个层面形成可复跑的自动化或半自动化证据。
4. 给出明确的验收结论：达到/未达到交付标准，列出未关闭缺陷及风险。

**不在本次范围**：多智能体自由对话、多文件工程、Connectors、协作/权限、自定义域名、邮件找回、录屏与账单材料；GitHub 仓库 public 状态与提交历史无法在本地独立核验，仅做工作区密钥与 `.gitignore` 扫描。

## 3. 测试策略与分层

| 层级 | 目标 | 方法/工具 | 执行环境 |
| --- | --- | --- | --- |
| 单元测试 | 纯函数与约束：静态检查、评分、HTML 提取、模板路由、密码哈希、限流、沙箱文档构建 | `tsx test/unit-qa.ts`，无第三方依赖 | 本地 Node 26 |
| 接口/契约 | 状态码、字段、鉴权、SSE 事件、版本、发布、KV、账号 | `tsx test/api-qa.ts`（fetch + CookieJar + SSE 解析） | 隔离库 3200 |
| 安全 | 越权、注入、密钥泄露、Cookie 属性、限流绕过、CSRF/SSRF 面、沙箱逃逸 | 接口断言 + 源码审查 + 浏览器实测 | 3200 + Chrome |
| 并发 | 同项目互斥、双路并行、KV 并发、多用户隔离、发布幂等 | `Promise.all` 并发请求 | 3200 |
| 异常/韧性 | 402/429/断流/补丁失败/编辑失败不覆盖/重启恢复 | 假模型服务 `test/fake-llm.mjs` + 隔离库 3201 | 3201 |
| WebUI | 首页、生成、时间线、预览交互、版本、发布、移动端 | 浏览器自动化 + Chrome 无头截图 | 3200 + 线上 |
| 兼容性 | Chrome/Safari、375px、刷新/换设备 | Chrome 实测；Safari 人工记录 | 本地 + 线上 |
| 持久化 | 进程重启、跨会话、跨设备、访客隔离 | 重启实例 + 新 CookieJar | 3200/3201 |

**原则**：
- 大批量功能与并发用例使用 `MOCK_MODE=1` 的隔离实例，确定性高、不消耗模型额度、不影响 3100 现有数据。
- 真实模型链路上只做 1 次创建 + 1 次编辑的轻量验证（本地 3100），线上只做只读与首屏验证，避免打挂演示服务器。
- 发现缺陷只记录、不修复产品代码；必要时仅调整测试侧脚本。
- 所有写操作使用新建游客/测试邮箱，不使用个人账号；线上不发布、不删除、不压测。

## 5. 准入与验收标准

### 5.1 准入

- `npm run typecheck` 与 `npm run build` 通过；E2/E3 健康检查 `ok=true`。
- 现有 `npm run smoke` 可在 E2 跑通（作为回归基线）。
- 测试账号、隔离数据库、端口均就绪；线上健康检查 200。
- 已确认产品说明、README 与说明文档。

### 5.2 验收标准

| 条件 | 标准 |
| --- | --- |
| P0 用例 | 100% 执行，通过率 100%（允许非产品缺陷的环境性跳过并留证） |
| P1 用例 | 执行率 ≥95%，通过率 ≥90% |
| 缺陷 | 无未关闭 S1（阻断）/S2（严重）；S3 需有明确影响说明与规避建议 |
| 核心闭环 | A1-A12 中可在本环境验证的项全部通过 |
| 冒烟 | `npm run smoke` 22/22 PASS（隔离 Mock 环境） |
| 线上 | 首屏、健康、分享页、375px 轻量验证通过 |
| 文档 | 测试方案、用例与执行报告、缺陷清单齐全，结论明确 |

### 5.3 缺陷分级

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| S1 阻断 | 白屏/核心闭环不可用/数据丢失/密钥泄露/越权 | 生成 500、分享页空白、Key 出现在前端 |
| S2 严重 | 主功能失败或版本被覆盖、发布不可用、沙箱逃逸 | 编辑失败覆盖旧版、访客可读所有者数据 |
| S3 一般 | 次要功能缺失、限流缺失、移动端明显破版、无安全响应头 | 无生成限流、375px 横向滚动 |
| S4 轻微 | 文案、交互细节、可访问性 | 提示语不清、按钮状态不明确 |

## 6. 风险与应对

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| T1 | 真实模型慢/限流/额度不足 | 真实链路验证阻塞 | 仅 1 次轻量创建；失败则以 E2/E3 证据为准并记录 |
| T2 | 测试污染现有库 | 影响开发环境 | 使用 `data/qa-*.db` 隔离库；不删除、不改 3100 数据 |
| T3 | 演示服务器被打挂 | 影响交付链接 | 线上只读 + 单次首屏/分享页访问，不并发、不生成 |
| T4 | 浏览器自动化能力有限 | WebUI 覆盖不足 | 接口与 DOM/源码断言兜底；关键路径用浏览器代理实操截图 |
| T5 | Safari 无自动化 | 兼容性覆盖不全 | Chrome + 375px 实测；Safari 列为未执行风险项 |
| T6 | 数据库异常难注入 | 异常覆盖缺口 | 代码审查 + 重启/锁库风险说明；不作为验收阻断 |
| T7 | 客户端探针数据可伪造 | 评分可信度 | 按设计文档中的已知限制记录，验证"仅辅助择优"定位 |
| T8 | 测试脚本改动产品行为 | 结论失真 | 测试代码仅放 `test/` 与 `script/`，产品源码零修改 |
